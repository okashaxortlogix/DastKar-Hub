# Discovery Events & Position Tracking

## 1. Overview
The `discovery_events` infrastructure tracks buyer interaction telemetry to evaluate listing performance, click-through rates (CTR), conversion, and the empirical exposure received by newly verified artisans.

---

## 2. Event Types
- `product_impression`: Rendered in listing view or recommendation shelf.
- `product_click`: Buyer selected product card to view details.
- `search_result_impression`: Rendered as part of a keyword search response.
- `search_result_click`: Selected from keyword search results.
- `category_product_impression`: Rendered in category browse.
- `maker_impression`: Studio card rendered in artisan directory or spotlight.
- `maker_click`: Studio profile opened.
- `add_to_wishlist`: Product added to buyer wishlist.
- `add_to_cart`: Product added to checkout bag.
- `purchase`: Successful order checkout.

---

## 3. Position Tracking
Each event optionally captures:
- `surface`: e.g., `search`, `category`, `homepage_trending`, `homepage_recommended`, `new_makers`.
- `position`: 1-indexed listing rank on the screen (e.g., position 1 through 12).
- `product_id`, `seller_id`, `category_id`.
- `session_id`: Anonymous client session token (stored in `localStorage` as `dastkar_session_id`).
- `user_id`: Authenticated user ID (if logged in).

---

## 4. Fraud & Anti-Abuse Protection
To prevent ranking manipulation:
1. **Self-Click Rejection**: Clicks or impressions generated by the seller on their own products are automatically discarded from ranking signals.
2. **Session Debouncing**: Duplicate impression or click events for the same product within a 5-minute rolling window from the same session are ignored.
3. **Immutable Client Boundaries**: Ranking scores, sales counts, and trust indicators are strictly calculated and persisted on the backend and cannot be overridden by client request payloads.
